# Technical decisions and design

**Offline-first, no back end.** The device's IndexedDB is the source of truth. Gyms have bad signal, and a logging app that hangs waiting for the network is useless. Syncing between devices will come later, _on top of_ the local database.

**Ready to sync, from day one.** Even without a server, the schema follows rules that make future sync easier:

- IDs are UUIDs generated on the client (`crypto.randomUUID()`), so there are no ID conflicts between devices.
- Every record has `createdAt`, `updatedAt` and `deletedAt`. Deletion is **soft**: the record is marked, so another device can learn that it was removed.
- Every table has an index on `updatedAt`, to answer "what changed since the last sync?".
- Seed exercises have **fixed IDs**. If each device drew its own, the same "Bench Press" would show up twice after syncing.

**Database migrations.** The schema is versioned (`db.version(1)`, `db.version(2)`...) and old versions are never edited, because each user's phone can be on any of them. v2 introduced bilingual names and merged duplicate exercises (e.g. "Bench Press" and its Portuguese twin) by moving every set to the exercise that stays, with no history lost; v3 created workout splits and put the existing routines into one. Tests build old databases and check each migration.

**Two languages, no library.** Two typed dictionaries: `pt.ts` is the source and `en.ts` must have exactly the same keys, or the project does not compile. Plurals and texts with values are functions. For two languages, a library such as react-i18next would be extra weight and complexity.

**Load is always in kg.** The database stores `weightKg`. Conversion to lb happens only when displaying, so there is never "half-converted" data.

**Indexes shaped by the real queries.** `[workoutId+position]` returns the sets of a workout in order; `[exerciseId+completedAt]` returns an exercise's history over time (sets that are not completed, with `completedAt = null`, stay out of the index automatically).

**Backup is untrusted input.** Importing validates and copies every record field by field, de-duplicates exercises by name and never leaves a stray in-progress workout, so a malformed file cannot leave broken data behind.

**Update prompt, not automatic.** When a new version ships, the app shows "New version available" instead of reloading on its own and interrupting a set.

**Persistent storage.** On startup the app calls `navigator.storage.persist()` so the browser does not evict the data when space runs low.

**TypeScript 6.0, not 7.0.** `typescript-eslint` does not support TS 7 (the native rewrite) yet. 6.0 is stable and keeps ESLint's TypeScript rules working.

**A restricted design system inside Tailwind itself.** The default color, radius and shadow scales are wiped in `@theme`. Only Encore's tokens exist, so `bg-blue-500` or `shadow-lg` do not even work.

## Design

An old-school gym look with a minimalist structure: _grit is the texture, minimalism is the structure._

- Near-black background with a subtle grain (an SVG generated by the browser, no image) and a faint warm glow from the top, like a lamp over the bench.
- **One** accent color (red), only on primary actions and records.
- "Stamp" logo: EN / CO / RE stacked, with the RE (again) in red; letters drawn in rectangles, no font dependency.
- Oswald (condensed) for headings and big numbers, Inter for body text, tabular numbers for loads and reps.
- Three surface levels (background < cards < sheets/bar) with a 1px light line on the top edge of each, so surfaces read as lit from above. The primary button is the one point of red light on the screen. Light comes only from named tokens: no ad-hoc gradients or shadows.
- Thick, square borders, 2 to 4px radius.
- Short, dry motion, only when it helps (loops only for living things: the in-progress pulse and loading skeletons): sheets that slide up, a slight slide on screen change, a ✓ that "stamps", a nudge when rest ends and a print glitch on the logo when the menu opens. All of it is off with "reduce motion".
- Touch targets of at least 48px and 16px input fonts (iOS does not zoom).
